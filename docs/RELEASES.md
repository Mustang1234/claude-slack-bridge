# 릴리스 노트

## 1.6.1 채널 감시 통합

1.6.0 은 지킴이 지연·채널 전체 재조회·첫 실행 일괄 등록 결함이 있어 태그하지 않았다. 1.6.1 부터 쓴다.

기존 설치는 Claude Code의 `permissions.allow`에 다음 항목을 추가해야 한다.
누락하면 --all 또는 --thread-poll 기동이 권한 검사에서 막힐 수 있다.
기존 `Bash(*claude-slack-bridge monitor --thread *)` 항목도 유지한다.

```json
"Bash(*claude-slack-bridge monitor --all*)",
"Bash(*claude-slack-bridge monitor --thread-poll *)"
```

- 지킴이는 다른 폴러의 예약 큐를 기다리지 않고 공유 429 cooldown만 따른다.
  replies는 1.5.1처럼 한 페이지만 읽고 기본 5초 대기를 유지한다. HTTP·429 지연은 별도다.
  기존 건강 판정의 문맥을 유지하기 위해 지킴이에 oldest는 적용하지 않았다.
  따라서 100개를 넘는 오래된 스레드의 한 페이지 조회 한계는 남아 있다.
- --all 첫 실행은 가입 목록을 기준선으로 저장한다. 기존 watched만 감시하고,
  이후 새 채널 및 재합류 채널은 합류 시점부터 감시한다.
- 일반 채널은 새 최상위 글을 한 페이지씩 이어 읽고, 알려진 부모를 회차당 최대 3개씩
  순환한다. 부모별 답글은 마지막 ts 이후 최대 3페이지다. 처음부터 알지 못한 부모는
  --track으로 등록한다. 부모 수가 많으면 답글 발견에 여러 회차가 걸릴 수 있다.
- --untrack은 상태를 삭제하고, 재등록은 현재 시점부터 읽는다. 연속 봇 수는 0에서
  시작한 뒤 새 발화로 계산한다. 멘션 없는 --any-reply는 작업 중 표시를 켜지 않는다.
- 전달·명령 원장은 접근할 때 7일 넘은 처리 기록을 정리한다. inbox는 그대로 보관한다.
- 장애와 회복은 대상별로 한 번씩 기록한다. thread_not_found는 자동 해제한다.

inbox 기록과 stdout 출력은 원자적이지 않다. 기록 직후 종료하면 자동 출력이 생략될 수
있으므로 inbox를 확인해야 한다. 이번 변경에는 소비 확인 프로토콜이 포함되지 않았다.
