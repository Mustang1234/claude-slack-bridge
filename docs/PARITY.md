# ntfy → Slack 기능 이식 인벤토리

판정 범위는 `ntfy_pool.py`, `ntfy_listen.py`, `notify.py`, `ntfy_caffeinate.py`의 실행 코드 전체와, 실제 운용 호출 경로를 확인하기 위한 `.claude/commands/ntfy-*.md`, `notify.md`이다. 주석에만 있는 계획은 기능으로 세지 않았다. 현재 정상 경로는 `hold → supervise-start → watch → caffeinate on`, 수신 후 `notify.py`로 응답하고 `watch`를 다시 띄우며, 종료는 `stop → caffeinate off → release`이다. `listen`은 디스패치 가능한 코드지만 운용 문서가 명시한 구방식이다.

`본질기능`은 ntfy가 아니어도 “자리를 비운 동안 알림을 받고 세션별로 답장한다”는 목적에 필요한 성질을 뜻한다. `ntfy제약`은 공개·무인증 토픽, 고정 토픽 구독, ntfy 캐시·레이트리밋·프로토콜 또는 그것을 보완하려고 생긴 장치를 뜻한다.

## 확인 못 한 것

- `POOL_SIZE=8`에서 **8이라는 수를 선택한 근거**는 네 코드 파일과 허용된 명령 문서에 없다. 동시 세션 용량을 제한한다는 효과와 고정 풀을 미리 만든다는 사실만 확인했다.
- 토픽을 **미리** 8개 만드는 직접적인 설계 결정 기록은 없다. 코드와 운용상 각 슬롯 토픽을 폰 ntfy 앱에서 구독해야 하고 hold 시 즉시 토픽이 필요하다는 점은 확인되지만, 지연 생성 대신 사전 생성을 택한 이유는 추론이다.
- `TOPIC_RANDOM_BYTES=42`는 `token_urlsafe(42) → 56자`, 접두사와 합쳐 64자라는 계산은 명시돼 있다. 요구된 엔트로피 수준이나 왜 최대 길이를 완전히 채워야 하는지에 대한 별도 보안 근거는 없다.
- `CURSOR_STALE_SEC=10시간`은 ntfy 캐시 12시간보다 먼저 ID 커서를 포기하려는 값이다. 정확히 2시간 여유를 둔 이유는 없다.
- `SEEN_MAX=200`, `ECHO_GRACE=1.2초`, 감시자 `--max-hours=8`, `UNKNOWN_PID_GRACE_SEC=600초`의 정확한 수치 산정 자료는 코드에 없다. 각각 중복 창, 발신-ID 기록 경쟁, 감시자 교대, PID 미상 오회수 방지라는 기능적 이유만 확인했다.
- `ntfy_pool.py:66-68` 주석은 리스너가 30초마다 heartbeat를 찍는다고 하지만 현재 정상 `supervise` 경로의 `POLL_INTERVAL`은 25초이고, 구 스트리밍 경로는 서버 keepalive 약 45초마다 갱신한다. “30초”가 과거 값인지 보수적 설명인지 확인할 수 없다.
- Slack MCP 서버가 로컬 Mac에서 Claude 세션과 함께 실행될지, 별도 상시 호스트에서 실행될지 주어진 코드만으로 알 수 없다. 따라서 `caffeinate`는 배포 형태에 따라 “로컬에서 유지” 또는 “서버 운영 정책으로 대체”로 조건부 판정했다.
- Slack에서 한 Claude 세션을 어떤 단위(`thread_ts`, DM, 전용 채널)와 결속할지, 누가 새 스레드를 만들 권한을 가질지 요구사항이 없다. 이 문서는 고정 ntfy 토픽 풀을 없애고 명시적 `session_id ↔ Slack conversation` 매핑이 필요하다는 수준까지만 확정한다.
- 독립 MCP 서버가 Slack 수신 이벤트로 **이미 실행 중인 Claude 턴을 어떻게 깨울지**는 이 네 파일에 대응 사양이 없다. durable 수신과 wake/dispatch 분리는 유지해야 한다고 판정했지만, MCP transport만으로 가능한지 별도 host integration이 필요한지는 확인하지 못했다.
- `notify_phone()`은 떼어진 supervisor에서 `notify.py`를 SID 인자 없이 실행한다(`ntfy_listen.py:124-135`). 환경의 `CLAUDE_SESSION_ID`가 상속되는지에 따라 마감 예고가 슬롯 토픽 또는 메인 토픽으로 갈 수 있으나, 실행 환경을 보지 않았으므로 실제 목적지를 확정할 수 없다.
- 보조 문서의 수신 메시지 거부 규칙과 “거부 통보 10분에 1건” 정책은 문서에는 있으나 네 Python 파일에는 구현 호출 경로가 없다(`ntfy-chat-start.md:37-59`). 따라서 살아 있는 코드 기능으로 표에 넣지 않았다. Slack 이식 시 별도 정책 계층 요구사항인지 결정이 필요하다.
